# 需求文档：人机象棋 & 军棋（Tauri 2.0）

| 项 | 内容 |
|----|------|
| 产品名 | chess-game（暂定） |
| 形态 | 桌面端应用（macOS / Windows / Linux） |
| 对战模式 | 人机对战（Human vs AI）为主；预留双人对战扩展 |
| 棋种 | 中国象棋、军棋（暗棋/翻棋规则，见下文） |
| 版本 | v0.1.1 |
| 日期 | 2026-08-13 |

---

## 1. 背景与目标

用 Tauri 2.0 构建轻量桌面棋类应用：前端负责交互与渲染，Rust 后端负责规则引擎、局面校验与 AI 搜索，保证走法合法性与算力安全边界清晰。

### 1.1 成功标准（MVP）

- 可启动桌面应用，选择「象棋」或「军棋」进入对局
- 玩家可走棋；AI 在合理时限内回应对手
- 胜负、和棋、非法走法有明确反馈
- 核心规则与 AI 逻辑在 Rust 侧实现并通过单元测试

---

## 2. 用户与场景

| 角色 | 目标 |
|------|------|
| 休闲玩家 | 快速开局，体验完整规则与基础 AI |
| 进阶玩家 | 调节难度、悔棋、查看简单分析（后续） |
| 开发者 | 双棋种共享壳层，规则/AI 可独立演进 |

### 主要场景

1. 启动 → 主页选棋种 → 选颜色/先手 → 选难度 → 开局  
2. 点选棋子 → 高亮合法着法 → 落子 → AI 思考 → AI 落子  
3. 对局结束 → 结果页 → 再来一局 / 回主页  
4. 对局中：悔棋、认输、新开局、切换音效（可选）

## 3. 功能需求

### 3.1 通用（P0）

| ID | 需求 | 优先级 |
|----|------|--------|
| G-01 | 主菜单：象棋 / 军棋入口 | P0 |
| G-02 | 新建对局：选择先手、AI 难度 | P0 |
| G-03 | 棋盘渲染、棋子交互（点选/拖放至少一种） | P0 |
| G-04 | 合法着法高亮；非法着法拒绝并提示 | P0 |
| G-05 | 人机交替行棋；AI 异步计算不阻塞 UI | P0 |
| G-06 | 终局判定与结果展示（胜/负/和） | P0 |
| G-07 | 认输、重新开始 | P0 |
| G-08 | 悔棋（至少回退 1 个完整回合：己方+AI） | P1 |
| G-09 | 本地设置：音效、棋盘主题、默认难度 | P2 |
| G-10 | 对局记录导出（简单文本/JSON） | P2 |

### 3.2 中国象棋（P0）

| ID | 需求 | 优先级 |
|----|------|--------|
| X-01 | 标准 9×10 棋盘与初始布局 | P0 |
| X-02 | 全部棋子走法：将/帅、士、象/相、马、车、炮、兵/卒 | P0 |
| X-03 | 将军、应将、被将死后禁止送将 | P0 |
| X-04 | 吃子、过河兵、炮隔子打等规则正确 | P0 |
| X-05 | 终局：将死、困毙；可选简单长将/重复局面和棋策略 | P1 |
| X-06 | AI：至少 2～3 档难度（随机合法着 / 浅层搜索 / 更深搜索） | P0 |
| X-07 | 记谱：简易中文记谱或坐标记谱（后续可对接标准记谱） | P2 |

### 3.3 军棋（P0，范围已锁定）

**已确认（2026-08-13）**：首版军棋采用 **二人暗棋（翻棋）MVP**。传统「先布局再开打」二人军棋不在本期范围，标为 P2 扩展（`GameKind::JunqiClassic`）。

#### MVP：二人暗棋军棋（翻棋）

| ID | 需求 | 优先级 |
|----|------|--------|
| J-01 | 6×6 或约定规格棋盘；棋子背面朝上开局，随机洗牌放置 | P0 |
| J-02 | 翻子、移动、碰子（比大小）规则完整实现 | P0 |
| J-03 | 军衔大小、工兵挖雷、炸弹同归于尽、司令等特殊关系按选定规则表实现 | P0 |
| J-04 | 行营/铁路等若采用简化盘面，需在规则附录中写明；复杂盘面可二期 | P1 |
| J-05 | AI：基于信息集的启发式（可见己方+已翻公开信息） | P0 |
| J-06 | 终局：吃掉对方军旗或对方无子可动等（按规则附录） | P0 |

### 3.4 AI 相关（跨棋种）

| ID | 需求 | 优先级 |
|----|------|--------|
| A-01 | AI 在 Rust 侧运行；前端只收「思考中 / 最终着法」 | P0 |
| A-02 | 可取消思考（新开局、认输时打断） | P1 |
| A-03 | 难度映射为：深度、时间上限、随机性、评估函数复杂度 | P0 |
| A-04 | 象棋优先 minimax/alpha-beta + 简单评估；军棋用启发式+采样 | P0 |

## 4. 非功能需求

| ID | 类别 | 要求 |
|----|------|------|
| N-01 | 性能 | 常规难度 AI 响应目标 ≤ 2s；高难度可配置上限（如 5s）并展示思考状态 |
| N-02 | 正确性 | 规则引擎有单元测试；关键着法/终局有用例 |
| N-03 | UX | 60fps 级流畅拖拽/动画非必须；交互延迟体感应即时 |
| N-04 | 体积 | 发布包尽量精简（Tauri 相对 Electron 的优势需保持） |
| N-05 | 安全 | 规则与裁判在 Rust；前端不可「直接改局面赢」绕过校验 |
| N-06 | 可维护 | 象棋与军棋规则模块隔离；共享 UI 壳与通用对局会话层 |
| N-07 | 平台 | 优先保证开发者本机（macOS）；CI/发布覆盖 Win/Linux 为后续 |

---

## 5. 范围外（本期不做）

- 联网对战、账号、排行榜  
- 在线观战、录像平台对接  
- 完整职业级象棋引擎（如对接外部 UCI/UCCI 引擎可作为远期选项）  
- 传统二人军棋（布局阶段）、四人军棋、复杂铁路行营全规则盘（除非明确升级）  
- 移动端 / Web 纯浏览器版（Tauri 前端技术可复用，但非目标交付）

## 6. 里程碑建议

| 阶段 | 目标 | 产出 |
|------|------|------|
| M0 | 文档确认 + Tauri 2 脚手架 | 可 `tauri dev` 空白壳 |
| M1 | 象棋规则引擎 + 命令 API + 简易棋盘 UI | 人机可完整下完象棋 |
| M2 | 象棋 AI 多难度 + 悔棋/终局体验打磨 | 象棋 MVP 可玩 |
| M3 | 军棋（翻棋）规则 + UI + 基础 AI | 军棋 MVP 可玩 |
| M4 | 设置、主题、导出、打包 | 可分发预览版 |

---

## 7. 验收清单（MVP）

- [ ] 象棋：从开局到将死/认输全流程无崩溃  
- [ ] 象棋：至少 20 条规则单测通过（含马蹩腿、炮打隔子、送将禁止等）  
- [ ] 军棋：翻子/碰子/胜负判定正确  
- [ ] AI：两档难度行为可区分  
- [ ] 切换棋种互不影响状态  
- [ ] 非法 IPC/命令参数被后端拒绝

## 附录 A：象棋规则基线

采用中国象棋竞赛规则的常见子集：标准开局、走法、将军/应将、将死与困毙。长将、长捉等和棋细则 MVP 可简化为「重复局面 N 次判和」或暂不实现，需在实现前在 issue 中锁定。

## 附录 B：军棋规则基线（翻棋 MVP）

实现前需固化一张「军衔对照表」与「碰子结果表」（含工兵、地雷、炸弹、军旗）。建议单独文件 `docs/rules/junqi-dark.md` 在 M3 前补齐；未补齐前不开始军棋规则编码。
